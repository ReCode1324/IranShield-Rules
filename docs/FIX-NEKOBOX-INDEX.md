# راهنمای اصلاح نهایی Workflow و NekoBox (نسخه ۲۰۲۶/۱۱/۰۵)

## علت شکست اخیر

لاگ GitHub Actions به خطای زیر رسید:

```text
AssertionError: No self-contained NekoBox publisher in Workflow
```

تست قبلی سعی می‌کرد متن خاصی از داخل فایل YAML استخراج کند. تفاوت نسخهٔ Workflow و تست در GitHub باعث شکست می‌شد، حتی اگر سایر مراحل درست بودند.

در نسخهٔ جدید تولید فهرست در **`scripts/publish.py`** انجام می‌شود. `scripts/catalog.py` تنها منبع نگاشت ۱۲ نام NekoBox به ۶ فایل SRS است. `tests/test_workflow_publish.py` مستقیماً همین اسکریپت واقعی را آزمایش می‌کند و دیگر متن YAML را به عنوان کد پایتون استخراج نمی‌کند.

## حتماً همهٔ فایل‌های اصلاحیه را با هم آپلود کن

فقط جایگزین کردن YAML کافی نیست! این فایل‌ها باید از **یک نسخه واحد** باشند:

```text
.github/workflows/update-rules.yml
scripts/build.py
scripts/catalog.py
scripts/publish.py
scripts/finalize.py
tests/test_workflow_publish.py
srslist.json
nekobox/srslist.json
```

بهترین روش، آپلود **تمام محتوای بسته ZIP نهایی در ریشهٔ شاخه main** است. اگر از بستهٔ اصلاحیهٔ کوچک استفاده می‌کنی، مسیر پوشه‌ها را دقیقاً حفظ کن و فایل‌ها را جداگانه داخل `main` آپلود کن. خود ZIP را در ریپو آپلود نکن.

## مراحل اجرا

1. تغییرات را در شاخهٔ پیش‌فرض `main` ذخیره/Commit کن.
2. در بخش Actions، ورک‌فلو `Twice-Monthly IranShield Rules Update` را دستی اجرا کن.
3. باید تست‌ها، دریافت منابع، نصب و تأیید sing-box، کامپایل و بازخوانی شش فایل SRS، انتشار NekoBox، بررسی SHA-256 و Commit همگی سبز شوند.
4. فهرست ثابت: `https://raw.githubusercontent.com/ReCode1324/IranShield-Rules/main/srslist.json`
5. زمان‌بندی: روزهای **۱ و ۱۵** هر ماه **03:17 UTC**. اجرای زمان‌بندی‌شده ممکن است با تأخیر یا حتی عدم اجرا در GitHub مواجه شود؛ وضعیت Actions را بررسی کن.

### حفاظت در مقابل انتشار ناقص

- اگر یکی از منابع **اجباری** در دسترس نباشد یا حجم/حداقل تعداد آن معتبر نباشد، بیلد متوقف می‌شود و فایل‌های نسخهٔ قبلی در GitHub تغییر نمی‌کنند.
- اگر SRS کامپایل نشود یا در خواندن مجدد با sing-box خطا داشته باشد، مرحلهٔ انتشار انجام نمی‌شود.
- `publish.py` قبل از نوشتن چهار کپی JSON وجود هرسه مورد را می‌سنجد: ۶ فایل `.json`، ۶ فایل `.srs` و هدر استاندارد `SRS`.
- `finalize.py` مطابقت ۱۲ URL و SHA-256 خروجی‌ها را کنترل می‌کند.

### آنچه تست شده / نشده

۱۶ تست آفلاین و یک اجرای شبیه‌سازی‌شده شامل ساخت از fixture، مسیر کامپایل و بازخوانی، انتشار، بررسی‌ها و Commit/Push به Git محلی با موفقیت انجام شده است. شبیه‌سازی برای کامپایل از یک CLI آزمایشی استفاده می‌کند، نه فایل باینری واقعی sing-box. به دلیل نبود دسترسی شبکه و دسترسی نوشتن به حساب GitHub شما، اجرای آنلاین منابع و کامپایل با نسخه رسمی روی GitHub را نمی‌توان از اینجا قطعی تأیید کرد. اولین اجرای موفق Actions معیار نهایی است.

## نکته دربارهٔ کلاینت

این JSON یک **فهرست آدرس SRS** است، نه فایل اشتراک پروکسی یا تنظیمات کامل NekoBox؛ برای بلاک تبلیغات و Direct ایران باید قوانین مربوطه را داخل کلاینت اعمال کنی. ریپوی private نیز برای لینک‌های مستقیم `raw.githubusercontent.com` نیاز به احراز هویت دارد.
